# Data Note

## Why No Data is Committed

This repository contains no raw or processed data files. There are two reasons:

1. **Bloomberg data** (scripts 06-10): The EURO STOXX 600 price history and BESG ESG scores
   are proprietary Bloomberg data. They cannot be redistributed without a Bloomberg licence.

2. **Simulated data** (scripts 01-05): The synthetic stock price dataset
   (`stockprices2500.csv`) and associated FICO-generated metadata (`shares2500_fixed.csv`)
   were provided as part of a university research project. Their redistribution is not
   authorised.

All `data/` subdirectories contain only a `.gitkeep` file to preserve the directory
structure in the repository. The `figures/` directory is likewise excluded (all figures are
regenerated by the pipeline).

## Required Input Files

To reproduce the results, place the following files in `data/raw/` before running:

### Simulated pipeline (scripts 01-05)

| File | Description |
|---|---|
| `data/raw/stockprices2500.csv` | 2,500 synthetic stocks, ~5,000 daily prices. Columns = tickers, rows = dates. |
| `data/raw/shares2500_fixed.csv` | Per-stock metadata. Required columns: `ticker`, `mu` (expected return), `esg` (ESG score, 0-100 scale), `sector`. |

### Bloomberg pipeline (scripts 06-10)

| File | Format | Description |
|---|---|---|
| `data/raw/SXXP_FINAL.csv` | Bloomberg export; semicolon-separated; 5 header rows before data | Daily closing prices for EURO STOXX 600 constituents |
| `data/raw/TICKERS.csv` | Standard CSV | Per-stock metadata. Required columns: `ticker`, `esg_score` (Bloomberg BESG, 1-10 scale), `sector`, `country`. Additional optional columns: `name`, `isin`, `cur_mkt_cap`, `gics_industry_name`, `environmental_score`, `social_score`, `governance_score`. |

## Bloomberg ESG Scale

Bloomberg BESG scores are reported on a 1-10 scale (higher = better ESG profile). The
pipeline maps these to the common 0-100 optimisation scale used by both datasets:

```
esg_final = (BESG - 1) / 9 * 100
```

This maps:
- BESG = 1    ->  esg = 0
- BESG = 5.5  ->  esg = 50
- BESG = 10   ->  esg = 100

The original BESG score is retained as `esg_raw` in the processed metadata for traceability.

To convert a 0-100 ESG floor back to its native BESG equivalent:
```
BESG_equivalent = floor / 100 * 9 + 1
```

For example, ESG floor = 55 corresponds to BESG >= 5.95.

## Bloomberg File Format Notes

`SXXP_FINAL.csv` has Bloomberg-specific formatting:
- Separator: semicolon (`;`)
- Header structure: 5 rows before the data begins (Bloomberg metadata rows: field name,
  field description, currency, etc.)
- Missing prices: encoded as the string `"#N/A N/A"` (not a standard NaN)
- Date column: first column, Bloomberg date format

Script `06_load_bloomberg.py` handles all of these format quirks automatically.

## Solver Requirement

All optimisation scripts require Gurobi 13 with a valid licence (academic or commercial).
Free academic licences are available at:
https://www.gurobi.com/academia/academic-program-and-licenses/

The Gurobi licence key file (`gurobi.lic`) is excluded from the repository by `.gitignore`.
Run `python check_gurobi.py` from the project root to verify your licence and solver
configuration before running the pipeline.

---

## Reproducibility

Given the required input files and a valid Gurobi licence, the full pipeline is deterministic:
- All random seeds are fixed where relevant (bootstrap B=1,000 uses a fixed seed)
- All parameters are defined at the top of each script; change only there, never inline
- Every script writes a log (`.txt`) recording all parameter values, intermediate statistics,
  and methodological choices
- Intermediate outputs are saved at each step so downstream scripts can be re-run
  independently without re-running the full pipeline
